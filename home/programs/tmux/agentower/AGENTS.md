# Agentower

Notes for `home/programs/tmux/agentower/`.

## agentower-verify (Agentower e2e)

After changing `home/programs/tmux/agentower/agentower-main.ts`, `home/programs/tmux/agentower/agentower.tsx`, `home/programs/tmux/agentower/restore.ts`, `home/programs/tmux/agentower/agentower_e2e_harness.ts`, or `home/programs/tmux/agentower/agentower_e2e_test.ts`, run `.claude/skills/agentower-verify/agentower-verify.ts` (or invoke the `/agentower-verify` skill). It spins up an isolated `tmux -L agentower-e2e-$PID` server, runs every e2e scenario in `agentower_e2e_test.ts` under `bun test`, and emits a JSON verdict. It counts the `(pass)` / `(fail)` lines of the report and fails when they disagree with the summary, so a run that printed no per-test lines cannot read as green. The sandbox replaces `HOME`, so the harness points `BUN_RUNTIME_TRANSPILER_CACHE_PATH` back at the real cache; otherwise Bun writes its transpiler cache under the sandbox, one of which is the tracked `fixtures/task-progress-home`. Most popup scenarios exit through Escape and the rest through a jump or prefix+e; the dashboard scenarios exit through `q`. A broken quit path therefore fails CI-style rather than leaking a stuck Agentower into the sandbox. Do not claim Agentower changes are complete while `ok: false`.

## Agentower binary (prefix+e)

**Agentower** is the tmux `prefix+e` popup that lists the Claude Code / Codex / opencode panes with their status and jumps to the selected one (older records call it the tmux picker).

The same binary with `--dashboard` is the always-on variant for a second display: the `agentower` zsh function (`home/programs/zsh/init.zsh`) runs it in a terminal window outside tmux, where it skips the `TMUX` guard and the prefix+e chord, ignores Escape, quits on `q` or Ctrl+C, and stays open after a jump. The function sends stderr to `~/Library/Logs/agentower-dashboard.log`, because Ink draws each `tmuxRun` error above the frame and a dashboard open through a tmux server restart would print one a second. The jump is the popup's `jumpTo` unchanged: with no `-c`, tmux switches the client it resolves as the most recently active one, and with `focus-events on` a focus change counts as activity as well as keys and mouse. Started inside tmux it would resolve to the client showing the dashboard, so the zsh function refuses the dashboard when its tty is one of tmux's panes. It checks the tty rather than `TMUX` because a terminal app launched from a tmux pane hands `TMUX` and `TMUX_PANE` to every window it opens later, and for the same reason it starts the binary with both unset; the e2e scenarios run `--dashboard` inside tmux on purpose and attach real clients through the harness's `attachClient`.

`--sidebar` is the dashboard laid out for a 48-column WezTerm pane beside tmux: In `home/programs/wezterm/wezterm.lua`, `Cmd+E` splits one off on the left of the tab, then hides and shows it by zooming the tmux pane, so the process keeps running and its selection and `p` survive; `Cmd+Shift+E` moves the focus between it and the tmux pane (opening or unhiding it first); `q` closes it. The sidebar is recognised by `--sidebar` in its argv, not by the executable name: a tmux started by `agentower --restore` has the same name in front. WezTerm starts the binary itself with `TMUX` and `TMUX_PANE` unset and stderr in the dashboard's log, so the zsh function is not involved. Its lifecycle is the dashboard's; only the layout differs, and only under `mode === "sidebar"`, so the popup and the dashboard draw as before. Each pane is two rows (`COMPACT_CARD`, so `visibleWindow` and `cardIndexAt` apply unchanged): `repo(worktree) · branch` with the status icon, then the task line with the elapsed time. `sidebarLocation` (`format_helpers.ts`) fits the location into the row: a branch named like the worktree is dropped, the branch is cut first down to eight cells, then the repo name, and the worktree is kept. The agent, the state (the wait reason when there is one) and the context usage are not on the rows but on the preview's bottom edge (`previewFooterTokens`, drawn by `Card`'s `footer`), and the preview is closed until `p`; opened, it leaves the list at most 65 % of the column. The Usage card stacks there (`usageStackedRows`): the agent on a heading row, then a gauge row per window, because the popup's one row per agent with bars needs 60 cells. After a jump the sidebar writes an OSC 1337 `SetUserVar=agentower_jumped=<base64 "pane time">`, and `wezterm.lua`'s `user-var-changed` hands the focus back to the tmux pane; the dashboard does not write it. S107–S110 and S114 in the e2e suite run it at 48×60. The selection follows the tmux client beside it: `wezterm.lua` passes that WezTerm pane's tty as `AGENTOWER_CLIENT_TTY`, and on start and every tick the sidebar reads the `pane_id` of the client with that `client_tty` from `list-clients`. It moves the selection only when that pane differs from the one it last followed and is listed, so a `j`/`k` stays until the client moves, and a pane that is not listed yet (a shell window, hidden by `w`) is followed once it is. The tty is matched in `list-clients` because `display-message -c` with a tty no client has answers for another client, and the most recently active client can be a tmux in another WezTerm window. Without the variable the sidebar does not follow; the dashboard never does.

`f` switches the list between the agent panes and the **free windows**: the tmux windows in which no agent pane is live (a window whose agent has exited counts as free; the unit is the window, so a spare window beside an agent's in the same session is listed), each shown as its active pane — its directory and branch, then that pane's command followed by the commands of the window's other panes (`zsh  + node, zsh`) — longest untouched first by `window_activity`. A row names neither the session nor the window, so two free windows in one directory running the same command differ only in the elapsed column and the preview. The window Agentower itself runs in (`TMUX_PANE`, when it is a real pane as in the e2e suite) is left out. Enter jumps there and starts nothing. A free window is a `PaneRow` of that pane with every `@pane_*` value blanked, which is what lets selection, preview, `jumpTo` and the list geometry serve both screens. Startup calls `fetchPanes(false)` and resolves no free window; the git lookups happen on `f`, and each free window in a repository gets one `git --no-optional-locks status --porcelain` when the screen is entered. The mark is as of that moment — `±` for anything `git status` lists, untracked files included, `?` when the check failed or took over two seconds, so once the checks are back a blank means a clean tree or a directory outside any repository — and pressing `f` twice re-reads it. That `git status` runs with `-c core.fsmonitor=false -c safe.bareRepository=explicit`: it is the one git command Agentower runs that reads the index, in a directory the user may only have `cd`'d into, and without those a repository's own config could name a program to execute. A `filter.<name>.clean` in such a config is not closed by this. `n` / `w` / `m` / `M` and right-click do nothing on that screen.

`p` opens or closes the preview. In the popup each press is written to the global tmux option `@agentower_preview` (`on` / `off`), and the next popup starts from it rather than from the height, so the choice lasts as long as the tmux server; with the option unset, a short stacked popup starts closed and any other open. The write is awaited before the process exits, so an Escape right after `p` keeps it. The dashboard and the sidebar neither read nor write it.

`home/programs/tmux/config/tmux.conf`'s `bind-key e` invokes the AOT-compiled binary at `~/.local/share/agentower/agentower`, not the source. The entry point is `agentower/agentower-main.ts`; `agentower.tsx` exports `main()` and is reached through a dynamic import so that `process.stdin.setRawMode(true)` runs before the ink module graph. Bytes typed before that call sit in the tty's canonical queue and are lost: measured on Bun 1.4.2, keys sent to the tty before exec arrive 2 ms after ink mounts with the early switch and never without it. The Node API has no cbreak variant, so ISIG is off from that point and a Ctrl+C typed during startup reaches ink as input once it mounts instead of as a signal (`ctrl_c_before_mount_exits` in the bench); if `main()` hung before mounting, Ctrl+C would not get out.

`home.activation.compileAgentowerBin` in `home/programs/tmux/default.nix` builds the binary in two steps, after `installDotfilesDeps`: `tsc --noEmit -p agentower/tsconfig.json` (neither Bun nor its bundler looks at types), then `bun build --compile --minify --bytecode --format=esm`. Bytecode moves parsing of the module graph to build time: first paint went from 55 ms to 39 ms against 66 ms for the Deno-compiled binary (`agentower-bench-baseline.md`). `--format=esm` is needed because bytecode defaults to CommonJS and the entry uses top-level await. The build reads `~/dotfiles/home/programs/tmux/agentower/agentower-main.ts`, not a store copy, because it needs the worktree's `node_modules`; for the same reason the stamp that decides whether to rebuild is a hash of those worktree files, taken by the activation, plus the Bun store path (the binary embeds the runtime). Nix only supplies the list of files, enumerated at eval time. Four flags carry weight. `--define process.env.NODE_ENV="production"` is what selects React's production build: `--compile` alone ships the development one, and `--minify` only trims size. `--no-compile-autoload-bunfig --no-compile-autoload-dotenv`: the popup opens in the pane's directory, and a compiled binary otherwise runs the `preload` of a `bunfig.toml` there and loads its `.env`; a unit test in `agentower_test.ts` pins both flags. `--define process.env.DEV="false"`: ink connects to react-devtools when `DEV` is `true` in the environment. `react-devtools-core` is a dependency only because ink imports it; leaving it out as `--external` makes the binary fail at start.

After `mv`, the activation runs the new binary once, because macOS charges about half a second to the first exec of a freshly written Mach-O of this size and the next `prefix+e` would otherwise pay it. Its exit code must be 2 — `main()`'s own guard on the missing `TMUX` — because that is also the only check that the binary starts at all; anything else keeps the old stamp so the next activation rebuilds. `restore.ts` is a dynamic import this run never evaluates, so a binary whose restore path is broken still passes; only the e2e with `AGENTOWER_E2E_BIN` covers it. The `</dev/null` keeps the warm-up off the `darwin-rebuild` terminal's stdin. (It is **not** needed to protect the terminal mode: Bun restores `icanon`, `isig` and `echo` at exit, measured on 1.4.2 after a run that sets raw mode and exits 2.)

Hash-skip keys on a sha256, taken at activation from the worktree, over the `.ts`/`.tsx` sources in `home/programs/tmux/agentower/` and `home/programs/tmux/shared/` (tests, the e2e harness, and `agentower-bench.ts` excluded), plus `home/programs/agents/lib/proc.ts`, `home/programs/agents/memo/summary-cache.ts`, `bun.lock` and both `tsconfig.json` files; the key also carries the Bun store path and a hash of `home/programs/tmux/default.nix` as evaluated, since the flags used are the evaluated ones. A source edit, a dependency bump, a Bun update, or a change to the build flags therefore triggers a rebuild on the next activation. The file list comes from the flake source, so a module that exists only untracked in the worktree is built in but not hashed.

Agentower covers three AI agents: `claude` / `opencode` / `codex`. Each agent has its own pane-status writer that emits `@pane_*` tmux options (claude: `claude-pane-status.ts` invoked by Claude Code hooks; opencode: in-process Bun plugin at `home/programs/opencode/plugin.ts`; codex: `home/programs/codex/scripts/codex-pane-status.ts` invoked by Codex CLI lifecycle hooks registered in `home/programs/codex/hooks.json`). All three follow the same single-shot script + stdin JSON pattern.

A row's directory, repository, branch and preview path come from `paneDir` (`format_helpers.ts`): `pane_current_path`, then `@pane_cwd` when that is empty. All three writers record the hook's `cwd` in `@pane_cwd`. Claude's value follows every Bash `cd` without moving the agent process, so `@pane_cwd` first would make the row follow every scratch directory; `EnterWorktree` and `claude -w` do move the process, and the row follows them. Whether a Codex or opencode session's directory can differ from its process's has not been observed. `pane_current_path` is the resolved path, so a pane started under `/tmp` reads `/private/tmp`. In the e2e, `createClaudePane` passes `startDir ?? cwd` to `new-window -c`, so a scenario that needs the two apart sets `startDir`.

When a pane running Claude Code or Codex is missing from the list, run `~/.local/bin/agentower-doctor.ts` (source `agentower-doctor.ts`). It compares each pane's `@pane_agent` with the agent it finds among the pane's descendant processes and labels the pane `OK`, `SUSPECT_MISSING_FLAG`, `STALE_FLAG` or `NORMAL`. It is a diagnostic only: Agentower keeps `@pane_agent` as its single filter rather than falling back to process detection.

Implications when editing Agentower source:

- `/agentower-verify` runs the suite against the source entry. Set `AGENTOWER_E2E_BIN=<path>` to run the same scenarios against a compiled binary instead — that is the only way to check the shipped artifact.
- To make changes visible to `prefix+e`, run `sudo darwin-rebuild switch --flake .#private` — the activation detects the source hash change and rebuilds.
- To iterate without a full rebuild, re-run the two steps directly from the repository root (arg set must match the activation):
  ```
  bun --no-env-file --no-install --config=/dev/null node_modules/typescript/bin/tsc --noEmit -p home/programs/tmux/agentower/tsconfig.json
  bun --no-env-file --no-install --config=/dev/null build --compile --minify --bytecode --format=esm --define 'process.env.NODE_ENV="production"' --define 'process.env.DEV="false"' --no-compile-autoload-dotenv --no-compile-autoload-bunfig --outfile ~/.local/share/agentower/agentower home/programs/tmux/agentower/agentower-main.ts
  ```
- Do not claim Agentower work is complete based solely on source-mode output — the binary is the thing users invoke.

## Session summaries

The first line keeps status/user label and the agent chip, followed by the cached task line (or the existing prompt when none exists). The second line holds repository/worktree and branch in `DOGRUN.fgDim`, then the wait/error reason or tool activity, with elapsed time and context usage on the right. Free windows keep their own renderer.

The memo prompt asks Haiku for a `作業:` line next to the daily-note summary: what the session is working on, as a noun phrase of at most twenty full-width characters. `parseLLMOutput` takes it out as `task`, so it never reaches the daily note, and the three memo scripts copy it into `~/.cache/agentower/summaries/<agent>/<sha256(fullSessionId)>.json` (state `version: 2`; a version 1 file holds a daily-note summary and is ignored). The daily-note summary is not shown as a fallback: it is a past-tense account of results, too long for the row and changing every turn. A run whose output has no task line publishes nothing, so the previous task line stays. Agentower reads through `home/programs/agents/memo/summary-cache.ts` after the first frame and on pane refresh; it never starts inference. Existing memo eligibility, input, daily-note requirements and debounce remain in force. A missing daily note can therefore leave the prompt fallback visible. There is no backfill or regeneration on a cache miss.

`summary-publisher.ts` reserves an epoch/generation concurrently with the existing inference and waits for it only after the existing daily/debounce success effects. Moving that await ahead of inference or debounce can widen the duplicate-generation window. Short cache updates use `/usr/bin/lockf` with an inherited fd; the lock is never held across inference and its inode is not unlinked. Failed or late publications leave the newest published generation intact.

`S_SUMMARY_FLOW` in the e2e suite starts each actual memo script with fixed provider responses, then observes popup/dashboard refresh and pane-session reuse. `AGENTOWER_SUMMARY_CAPTURE=1` saves ANSI and text captures under `.wadackel/qa/agentower-summary/` at 120/152 columns. Use `AGENTOWER_E2E_BIN` to exercise the installed binary. These checks never call the real model. The cache reader is included explicitly in `home/programs/tmux/default.nix`'s build inputs.

## Snapshot and restore

`agentower --snapshot` and `agentower --restore` (`restore.ts`) bring every tmux window and pane back after a reboot, with the agents resumed. `agentower-main.ts` branches on the two flags before raw mode and before ink is loaded: the restore prompt reads a normal line, and the snapshot runs every minute. The zsh function hands any argument list containing either flag straight to the binary.

`launchd.agents.agentower-snapshot` (`home/programs/tmux/default.nix`) runs `--snapshot` every 60 seconds into `~/.local/state/agentower/snapshots/<start_time>.json`, one file per tmux server, so the small server right after a reboot cannot overwrite the one being restored. Ten past servers are kept. A generation number counts past servers newest first and never the running one; `start_time` has one-second resolution, so a server started in the same second as the previous one takes its file for its own. A job runs only after `darwin-rebuild switch`, and `launchctl print gui/$(id -u)/org.nix-community.home.agentower-snapshot` shows its last exit code. Output goes to `~/Library/Logs/agentower-snapshot.log`.

Every tmux call goes through `tmuxArgs`, which adds `-u`. launchd gives the job no locale, and a client without UTF-8 rewrites control bytes and non-ASCII output to `_`: the `\x1f` separators vanish and every pane line fails to parse. `--snapshot` fails as a whole, keeping the previous file, when a line does not parse or the two tmux reads disagree, and writes nothing when `start_time` has changed by the end of the reads. A floating pane is not saved: `select-layout` refuses a layout that still holds one, so `tiledLayout` drops its leaves and re-sums tmux's checksum. It finds them in the `<...>` trailer, or, in a zoomed window, where tmux prints no trailer and reports no pane as floating (`pane_floating_flag` is 0 for every pane), by a position no split can have. A window or a server with nothing but floating panes is not saved. tmux stores a `\` in a session or window name doubled and prints it that way, so the saved name undoes it (`typedName`), or each restore would double it again. A pane counts as an agent under the same rule as the popup (`isStartupCodex`, `isLivePaneCommand`), plus `RESUME_ID_RE`, which also refuses a leading `-` because the id is typed after `claude --resume`; the directory is `pane_current_path`, because `@pane_cwd` follows the agent into scratch worktrees. tmux reads that from the foreground process on every format, so it is empty for a moment while a shell starts, and for as long as the foreground process cannot be inspected (`sudo`); a pane saved that way restores like one whose directory is gone.

`--restore` confirms, saves the running server, kills it, and rebuilds. It refuses to run from a pane or a popup of that server: the server's pid among its own ancestors (`insideByAncestry`), since a popup's terminal is no pane. The global option `@agentower_restoring` holds `<pid>:<start>` of the restore, set in the same tmux invocation as the first `new-session` and cleared at the end; the start comes from `ps -o etime=` on both sides, because `lstart` follows the locale and launchd runs the job with none, and the pid alone would not do, since pids wrap within the hour here. While that process runs, `--snapshot` writes nothing, so a half-built server does not become a generation mid-build. Once it is gone, as after a failed or killed restore, the server is saved again, but nothing is pruned while the option is set, so the generation a failure's message names survives until the retry. Every replaced server with something tiled is saved, and a failure names `generation + 1` exactly when it was. Agents are typed into the pane's shell with `send-keys` rather than run as the pane's command, so the shell survives them; when the saved directory is gone the command stays unsent. Do not reach for `resize-window` here: it pins `window-size` to `manual` and the window stops following the terminal.

**Never send `y` to `--restore` on the real server from a session inside it**: its `kill-server` ends that session. The e2e uses `setupInner`: a second server on a `-S` socket under a short `/tmp` directory (a socket path over 103 bytes fails), reached through a `tmux` shim first on `PATH`, with `innerEnv` as the whole environment. `TMUX_TMPDIR` alone is not enough: `TMUX` beats it, and a directory that does not exist is silently ignored. `spawnRestore` passes the command as several arguments so no shell runs `/etc/zshenv`, and checks `command -v tmux` in the pane right before exec. Its scenarios start with S86. The agent status hooks of Codex run in a shared daemon that looks only at `-L default`, so a pane on this inner server is never registered by a real Codex.

## agentower-bench (startup and input measurement)

`home/programs/tmux/agentower/agentower-bench.ts` measures what the popup costs and whether keys survive its startup, so a regression can be attributed to a phase instead of "it feels slow". It drives a binary inside the e2e harness's isolated tmux server and reads the `AGENTOWER_TRACE` marks the binary writes to stderr (`entry-start`, `raw-on`, `ink-module-eval-done`, `io-done`, `first-commit`, `input-received`, `tick-commit`, `render-us`, `tick-us`; off and free when the env var is unset). The `-us` pair carries a duration in microseconds rather than a timestamp: `render-us` is Ink's own timing of one `render(rootNode)`, so it is the frame's real cost, and one mark per frame makes it the frame counter that `tick-commit` is not (`tick-commit` sees App's commits only, never a frame driven by `Preview` alone).

```
home/programs/tmux/agentower/agentower-bench.ts --after <binary> [--before <binary>] [--pretty]
```

`agentower-bench-baseline.md` next to it holds the measured numbers with the commands that produced them, including the comparison of the Deno-compiled and Bun-compiled binaries. Absolute values move with the machine — read the before/after pair. The bench is excluded from the compile hash, so editing it costs nothing at activation.

It is deliberately **not** in `permissions.allow`: `--after` execs whatever path it is given, so it takes a confirmation each run. A `Bash(*agentower-bench*)` wildcard would also match a same-named file in any repository under review.
