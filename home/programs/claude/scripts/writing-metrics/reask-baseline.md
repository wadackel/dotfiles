# reask ベースライン記録（2026-09-19）

concise.md を「読者の判断を小さくする」形（Reader 節、決定事項で始めて読者待ちの 1 件で終える、判断材料を同じ返答に、作業途中の turn は済・今・次を言う）に書き換え、impl 完了報告に確かめ方を足した際の測定記録。

transcript は約 30 日で消え、過去の窓は再現できない。比較の基準はこの文書に記録された値だけで、再測定時に同じ `--from` を指定しても同じ母集団にはならない。

## 母集団の定義

- 単位は「そのターンの agent テキスト全体（前の実ユーザー発話以降の assistant テキスト連結、fence 含む）→ 次の実ユーザー発話」の組。最終テキストだけではない
- 除外: `isSidechain` レコード、`isMeta` ユーザー行、tool_result、`/subagents/` 配下、`<` 始まりの発話、中断マーカー、memo 要約、headless probe 定型、cross-session とシステム通知
- 分類の正規表現は和文のみ。英語セッションでの悪化はこの計測に映らない
- 粗集合は人手判定の約 2 倍を拾う。判定は `--list` の候補を読み、分類 1〜4（状態が書かれていない / 決めてほしいことが埋没 / 参照語が未定義 / 工程の語りが結論に混ざる）に仕分けて行う

## 再測定手順

1. `reask-rate.ts --from <測定日の 30 日前>` を実行し、記録時刻と組数を控える
2. `reask-rate.ts --from <同じ日付> --list` の候補を読み、分類 1〜4 / 該当なしに仕分ける
3. 比較は組数を揃える。上の基準値は 194 組で分類 1〜4 が 4 件なので、再測定の窓から最新 194 組を取って数える（組数が足りなければ、率でなく件数と組数を併記して判断を保留する）
4. 固定プロンプト 4 本を同じコマンドで採り、上の表と並べる

## 成功判定

分類 1〜4 の件数が同じ組数（194）で 4 件から半減（2 件以下）し、かつ固定プロンプトの表が悪化なし（before で満たした項目を維持、字数が 1.1 倍以内）なら「効いた」。満たさなければ blind 相対 judge の eval 基盤（固定ケース × 2 条件 × blind 採点 + release gate、`CLAUDE_CONFIG_DIR` 切替で旧 config と比較）に進む。

末尾を質問にする規則は、次の発話を「回答」に変えて聞き返し分類から外しうる。「末尾が質問で終わる組」の割合が上がっているのに分類 1〜4 が減っていない場合は、指標だけが動いたと判定する。
