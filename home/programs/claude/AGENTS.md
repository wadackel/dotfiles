# Claude Code configuration

Notes for `home/programs/claude/`: the settings, hooks, scripts, agents and skills linked into `~/.claude/`.

## Claude Code Integration

This repository includes comprehensive Claude Code configuration:

- **Settings**: `home/programs/claude/settings.json` (symlinked to `~/.claude/settings.json`). `idleCompaction` is off on both profiles: sessions on the work machine are resumed a day or a week later, and an unrequested compaction left them talking past the earlier conversation, so compaction stays an explicit choice
- **Agents**: `home/programs/claude/agents/` holds the reviewers `/gate` dispatches (`code-reviewer`, `security-auditor`, `database-reviewer`, `cloud-architecture-reviewer`, and `breaker-reviewer`, which runs the change in a `git worktree` `/gate` builds and reports only findings it proved with a command, dispatched on `/gate --break` or when the diff crosses a `human-review.md` boundary; `comment-reviewer` stays for Codex and other callers, while the Claude gate passes its rules to `code-reviewer` as `gate/references/comments-card.md`) and task agents (`debugger`, `refactoring-specialist`, `build-error-resolver`, `tdd-guide`, `code-simplifier` / `plan-simplifier`, `architect-reviewer`, `skill-guide-reviewer`). `autopilot-unit` and `autopilot-advisor` exist only for `/autopilot`: their frontmatter sets `experimental.cacheTtl: 1h`, because subagents otherwise write a five-minute cache and these two wait longer than that between turns, rewriting their whole context on each resume (observed in a greenline run); `/autopilot` dispatches them by `subagent_type` with no per-call `model`, which would override the definition. `autopilot-unit`'s body is the unit protocol (the phases, the controller's messages, the park rule, the report form), and the brief `/autopilot` sends carries only the unit's fields; `autopilot-advisor`'s body fixes its reply form and the read-only git it may run. A live autopilot run reads the skills afresh on each dispatch but keeps the definitions it started with (see the end of this section), so change both while no run is live. The language specialists (typescript, react, a11y, nix, rust, go, dart, deno) are no longer agents: each is a review card in `home/programs/agents/shared/plan/references/review-cards/<name>.md` (20–30 lines, `Trigger:` on line 2, `## Check`, `## Do not flag`), exposed to both agents through `skills/plan/references`. `/impl` and Codex `$impl` read the matching cards before writing, and `/gate` pastes them into `code-reviewer`'s prompt as `{focus_cards}`; across 72 gate logs the specialists found no MUST_FIX of their own, and the ten SHOULD_FIXes they caught alone were checklist items, so the checklist now rides with the generalist instead of a second model instance. `reviewer-dispatch-policy.ts` (`PreToolUse` on `Agent|Task`) guards only the six remaining reviewers (`GUARDED`); a dispatch to any of them must carry the `/gate` template's verdict rule and, for an agent without Bash, the `.gate.diff` path or inline hunks; `breaker-reviewer` carries the workspace sentence (`write only inside the breaker worktree and your temp directory`) in place of the read-only one, and `bash-policy.ts` refuses a bare `tmux` (or one naming the user's `default` socket), `launchctl`, `curl` and `wget` for a Bash call whose hook input names that agent in `agent_type` (it looks through the common wrappers such as `env`, `timeout`, `sudo` and `xargs` and their option arguments, into a shell's `-c` string (also as `-lc`, `-ec`) and into `env -S`, and a tmux counts as bare unless `-L` / `-S` comes before its subcommand; a process substitution or a script file is not looked into, which is why `/gate` reads and checks a breaker command before re-running it)
- **Scripts**: `home/programs/claude/scripts/` (symlinked to `~/.claude/scripts/`)
  - `claude-memo.ts`: Stop hook that writes session summaries to Obsidian daily notes. Debug: `$TMPDIR/claude-memo.log`
  - `bash-policy.ts`: `PreToolUse` hook (always active) that blocks prohibited command patterns. Rules defined in: `bash-policy.yaml` (same directory). Each segment is matched as written and with git's global flags (`-C <dir>`, `-c k=v`, `--git-dir`, …) stripped (`stripGitGlobalFlags` in `shell-utils.ts`), so a `git push *` rule would also catch `git -C . push origin renovate/x`
  - `write-policy.ts`: `PreToolUse` hook on `Write|Edit|MultiEdit` that blocks a personal identifier (`wadackel`, `tsuyoshi.wada`, host names) from entering a test or fixture path. A file that already carries the identifier stays editable, and `write-policy: allow` in the new content is the explicit escape. Tests: `bun test home/programs/claude/scripts/write-policy_test.ts`
  - `comment-metrics.ts <diff-file>`: counts added comment lines and comment blocks in a unified diff for `comment-reviewer`, which has no Bash; the Claude `/gate` no longer dispatches that reviewer, and Codex's twin still reads it. Same file types and marker set as the reviewer's Scope; exit 0 whatever the diff contains, 2 only for a usage error. Tests: `bun test home/programs/claude/scripts/comment-metrics_test.ts`
  - `claude-pane-status.ts`: Hook that writes session state to tmux pane options for Agentower. Invoked per event by argv[0] (SessionStart/End/UserPromptSubmit/PreToolUse/PostToolUse/PostToolUseFailure/Stop/StopFailure/Notification/PermissionDenied/CwdChanged/Subagent*). Unknown events are a no-op. Debug: pipe JSON to stdin with `TMUX_PANE` set
  - `writing-metrics/`: readability measurement tools for dialogue and generated documents (Japanese-English mixing density, reply volume percentiles, workflow-vocabulary contexts). Run every few weeks to compare Writing-norm metrics before and after. `lint.ts <file.md>` detects Writing-norm violations in a single Japanese Markdown file (the `/impl` final report is written as label-and-value lines by design, so its label-fragment rate is not a violation there); `fire-rate.ts --from 2026-08-31` tracks per-category violation density across transcripts — compare against `fire-rate-baseline.md` (committed 2026-08-30 snapshot) to judge the concise-style sentence constraints, plus bullet line and item length distributions by skill context and reply kind (2026-09-20 baseline in the same file). `reask-rate.ts [--from YYYY-MM-DD] [--list]` counts turn pairs (all assistant text since the previous real user message → next user message) and flags re-asks by Japanese regex; `--list` prints the candidates for hand curation into categories 1–4 (state missing / decision buried / undefined referent / process narration). Compare against `reask-baseline.md` (2026-09-19 snapshot) with `--from` set to 30 days before the measurement day
  - Running Claude script tests: `bun test home/programs/claude/scripts/<name>_test.ts`, or `bun test home/programs/claude/scripts` for all of them. Never pass `home/programs/claude/skills` as a whole: that directory holds symlinks into the shared skills and would run their tests a second time
  - When adding new scripts, add `"Bash(*<script-name>*)"` to `permissions.allow` in `settings.json` (wildcard prefix handles full-path invocations by Claude. `Bash(<script-name>*)` does not match path-prefixed invocations)
  - A compound or redirected invocation needs no entry of its own: Claude Code matches each subcommand of `&&`, `|`, `;` against the rules separately, and checks a redirect's target against the `Edit` / `Read` rules
  - Exception: Scripts called from `hooks` are not Bash tool calls, so adding to `permissions.allow` is not required
  - When adding new scripts, grant execute permission with `chmod +x` (execute bit is required for hook execution. Git manages mode as 100644/100755, so a commit is also needed)
- **rtk hook**: `home/programs/claude/hooks/` (linked as a whole to `~/.claude/hooks/`) holds `rtk-worktree-guard.sh`, the `PreToolUse` Bash entry that runs rtk's native `rtk hook claude`. The wrapper leaves a command containing `git` unrewritten when `cwd` is a linked worktree, because Claude Code's worktree isolation refuses `rtk git …`: it cannot tell which repository a git behind an unknown launcher targets (rtk 1.0.1 rewrites git even under `.claude/worktrees/`). rtk returns `allow` whenever `settings.json` has a matching allow rule, and Claude Code matches its rules against the rewritten `rtk …` command, so dropping that decision everywhere would send every rewritten command to the auto-mode classifier; the wrapper drops it whenever an interpreter or package manager (`RUNNERS`) appears as a word anywhere in the command, the same boundary as the git check, because auto mode disables their broad rules; a false match only costs one classifier call. Do not run `rtk init -g` or `--auto-patch`: they add rtk's own hook entry next to the wrapper and bypass it. The Claude side loads no `RTK.md` (the setup rtk calls `--hook-only`); Codex has no rtk hook and is pointed at `~/.codex/RTK.md` from `~/.codex/AGENTS.md`
- **Output styles**: `home/programs/claude/output-styles/` (symlinked to `~/.claude/output-styles`). `concise` is the global default via `settings.json`'s `outputStyle` key. Health check: `claude -p 'STYLE-CHECK' --settings '{"outputStyle":"concise"}'` must return `concise-active` — if not, the style is not being loaded
- **Gate**: `/gate` is the final step of `/impl` and the standalone review entry. Nothing is recorded to a file: checks run as plain commands and the conversation transcript holds their output. `/impl` sets the ref `refs/impl-base/<plan>` at its start; the gate diffs a snapshot of the working tree (through a copy of the index, uncommitted work and new files included) against it, checks that every Autonomous Verification bullet has a run that is not stale (`contract.md`, Tasks and checks), builds the breaker's `git worktree` in the session scratchpad and removes it at the end, and deletes the ref when it passes. A fixed blocker gets one re-review of the fix diff alone, so the Claude gate has two rounds, and a blocker still open after them goes through one closing pass by the main session (a spec Issue escalated, a security or human-review boundary blocker handed to the reader, another closed by a run that fails before the fix and passes after it, the rest escalated); the reply carries only what the reader must decide. The impl final report and the standalone gate reply are a short card defined in `impl/SKILL.md`: a result line, the bold groups `**何が起きたか**`, `**どこまで確かめたか**`, `**触ったファイル**` (a tree) and `**あなたがすること**` (`レビューしてほしい N か所`, `決める N つ`, `確かめてほしい N つ`), one item per line, at most 90 characters a line outside code blocks and 2,000 in all (`contract.md`, Final report), sent in the conversation only; under `/impl` the gate hands its items to the report instead of replying; Codex `$impl` writes the same card. `security-auditor` is selected by the data-flow triggers in `references/security-triggers.md`, `database-reviewer` by a change to a persisted format (`.sql`, `migrations/`, schema files), `cloud-architecture-reviewer` by IaC and workflow files; language concerns select a review card, never an agent. Codex `$impl`'s rule that a change to review-controlling skill markdown needs security review is deliberately not mirrored on the Claude side. Codex has no `$gate` skill: `$impl` carries its own Built-in Review
- **Shared contract**: `home/programs/agents/shared/plan/references/contract.md` defines every fixed string the plan / impl / gate skills, `check-plan.ts`, and the reviewer hook read (plan headings, Completion Criteria tags, the Requires User Confirmation form, `Final Audit + Review`, verdict vocabulary, the gate's file names); `interview.md` next to it holds the question format and the ask-or-decide judgment shared by both plan skills and `requirements-interview`, and read by both impl skills before they ask about a deviation; `human-review.md` next to it defines which changes a person reads in the diff, applied at plan approval and in the final report of both agents; `review-cards/` next to it holds the language and surface checklists that `/impl`, `$impl` and `/gate` read (see Agents above); `output-examples.md` next to it holds examples of the Claude `/plan` handoff and `/impl` final report in differing shapes, read just before either is written, and repeats the `## Plan ready` block and the report's fixed strings, so it changes together with `contract.md` by hand; no test reads it. `codex-plan-clarification-contract_test.ts` pins each entry against the files that carry it
- **Module**: `home/programs/claude/default.nix` manages symlinking to `~/.claude/`
- **Global instructions**: `home/programs/claude/global-instructions.md` is the symlink source for `~/.claude/CLAUDE.md`. Edit this file directly when modifying global settings. It is not named `CLAUDE.md` so that Claude Code does not load it a second time as this directory's project instructions, which would also keep this `AGENTS.md` from loading
- **`permissions.allow`**: `Edit(~/.claude/**)` allows skills to edit files under `~/.claude/` without confirmation dialogs. File permission checks only consult `Edit(path)` rules, and an `Edit` rule covers every file-editing tool (`Write` and `NotebookEdit` included), so `Write(path)` entries in `allow` are ignored and Claude Code warns about them at startup. This means new-file creation under `~/.claude/` — plan files, `settings.json`, `bash-policy.yaml` — is also covered by the same single rule; narrowing it would require splitting `Edit(~/.claude/**)` into per-subtree rules

Editing existing Claude Code config files (settings.json, skills, etc.) is immediately reflected — no `darwin-rebuild` needed (they are symlinked). Only run `darwin-rebuild` when adding *new* files that need new symlinks created. One exception: a running session keeps the agent definition it loaded at start. Claude Code watches `~/.claude/agents/` for edits, but that directory is a symlink into the Nix store whose entries are symlinks into this repository, so an edit to `home/programs/claude/agents/<name>.md` never reaches the watcher; the next `Agent` dispatch in the same session still uses the old definition, and only a new session (or `claude -p`) picks up the change.


## Project Directory Encoding Rules

Directory names under `~/.claude/projects/` are encoded from the project path: strip the leading `/`, add `-` as a prefix, and replace both `/` and `.` with `-`.
Example: `/Users/foo/github.com/bar` → `-Users-foo-github-com-bar`

## bash-policy

`bash-policy.ts` evaluates all Bash commands as a global `PreToolUse` hook.
- **Blocking behavior**: exit 2 → command not executed → stderr returned to Claude as error feedback → self-correction
- **Global rules**: `~/.claude/scripts/bash-policy.yaml`, currently `rules: []`. The `breaker-reviewer` restriction (see Agents) is in `bash-policy.ts` itself, so it stays active with no YAML rules
- **Project rules**: Create `.claude/bash-policy.yaml` and it will be auto-loaded by searching upward from `cwd` (already in global gitignore)
- **Rule format**: YAML with `pattern: "npx *"` + `message: "..."` (glob matching)

## Hook Data

Claude Code hooks receive JSON via stdin with common fields (`session_id`, `transcript_path`, `hook_event_name`, `cwd`) plus event-specific fields. `cwd` reflects the current shell cwd: Claude Code tracks Bash `cd` and updates the payload accordingly, so it is NOT stable for the lifetime of the session. Hooks that need a per-session stable key must scope on `session_id`, not on `cwd`. Stop hook: `stop_hook_active`. Notification hook: `message`, `title`, `notification_type`.

## `permissions.allow` Limitations

`Tool(**)` patterns (e.g., `Read(**)`) only cover paths within the project directory and `additionalDirectories`. For paths outside the project like `~/.claude/`, add `Tool(~/.claude/**)` separately. `Read(~/.claude/**)` and `Edit(~/.claude/**)` are needed; the `Edit` rule also covers `Write`.
