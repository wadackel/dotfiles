obsidian-web-clip に対して、オフラインでできる探索的テストを行い、バグを 1 件だけ探してください。

進め方:

1. `AGENTS.md` と `README.md` を読み、プラグインが何をするものかと、テストの書き方をつかむ
2. `pnpm install` のあと `pnpm verify` を実行し、今の状態が通ることを確かめる
3. `src/` の純粋な関数（`sanitize`、`filename`、`title`、`inline-tags`、`clip`、`triage` など）に、既存のテストが試していない入力をぶつける。崩れた HTML、極端に長い・空・制御文字を含むタイトル、Unicode の正規化違い、Markdown として意味を持つ記号、`test/attacks.ts` にない攻撃的な入力などを、使い捨てのテストや `node -e` で試す
4. 実際の Web ページの取得、Obsidian の起動、vault への書き込みはできないので試さない

報告の仕方（構造化出力）:

- 直し方が 1 つに決まるバグを見つけたら、失敗するテストを先に足してから直し、`pnpm verify` を通して `outcome: "pr"` にする。本文には、再現する入力、原因、`pnpm verify` の結果を書く
- 直すのに設計の判断（仕様をどうするか、互換性をどう扱うか）が要るものは、コードを変えずに `outcome: "issue"` にする。本文には、再現する入力、今の挙動、選択肢とそれぞれの影響を書く
- 見つからなければ `outcome: "nothing"` にし、`summary` に試した観点を短く書く
- 見つけたものが複数あっても、報告は一番影響の大きい 1 件だけにする
