# Replaying sessions to compare skill versions

A replay runs a past or synthetic request through `claude -p` once per arm (no skill, the old version, the new version) and compares what each run did. Each run takes minutes and the dollars of a real session (three replays of one comparison cost about $44, and one comparison of three arms over two tasks ran into the five-hour usage limit), so replay only a change to how a skill behaves, and fix the bar before running: the observable criteria, and how many arms must meet them. Two runs per arm could not separate two wordings of the same skill; a tie or a split calls for more runs of the arm in question, not a verdict.

## Isolation

A replay is an ordinary `claude` session with this machine's settings, so it can do whatever those settings allow without asking. Close what the request does not need before relying on anything else.

- Replay in a clone at the commit, not a worktree: a worktree reads the original repository's memory, while a clone gets the memory of that time. In the clone, delete every ref but `main`, run `git gc`, and remove `origin`, or the model finds the future commits, fetches them back, or pushes the rehearsal's commits.
- The real `CLAUDE.md`, memory, and skill listing carry real paths and later facts. Add a short preface that the run is a rehearsal, and deny what reaches outside: `--disallowedTools 'Bash(gh:*)' 'Bash(git push:*)' 'Bash(sudo:*)'` at least, and `Bash` as a whole when the replay does not need it. For a public repository, assume the web can find the real issue.
- Writes are not confined to the run's directory. This repository's settings allow `Edit(**)` and list `~/.claude`, `~/dotfiles`, and `/tmp` as additional directories, so in any permission mode a run can edit the real skills and settings; observed runs under `/tmp` wrote fixtures into other `/tmp` directories. Put each run in a directory outside those, such as `~/.cache/replay-<id>/`, and deny `Edit(~/dotfiles/**)`, `Edit(~/.claude/**)`, `Edit(//tmp/**)`, and `Edit(//private/tmp/**)`: a probe run from `~/.cache` wrote its own file while all four were refused. Not under `$TMPDIR`: it is `/var/folders/…`, and the settings deny `Edit(//var/**)`, so a run there cannot write even its own directory. These denies bind only the file tools: a replay with Bash can still write wherever its commands reach (`bun`, `cp`, `tee` and `sed` are allow-listed), so give a replay Bash only when the request needs it, and then with Claude Code's sandbox limiting writes to the run directory (not tried here).
- `--permission-mode acceptEdits` replaces the default `auto` mode, so the broad interpreter and package-manager rules that auto mode sets aside apply again without the classifier; one more reason to deny `Bash` when it is not needed. It still refuses writes under the project's `.claude/`, allow rules included: have the run write the skill to a `skills/` directory and copy it into `.claude/skills/` for the next step, rather than bypassing permissions.
- `bash-policy.ts` holds back the first `gh pr|issue create` of a session with a pointer to the writing skill; set `CLAUDE_DELIVERABLE_HINT_SKIP=1` in an arm that must run without that skill, or its no-skill arm is told to load it.
- Keep hooks on. `bash-policy.ts` is what keeps a replayed `breaker-reviewer` or `exploratory-session` off the user's tmux server and GitHub, and the agent-browser SessionStart hook gives the replay its own browser session instead of the parent's. The Stop hook already skips a `claude -p` started from a Claude Code session; `CLAUDE_MEMO_SKIP=1` makes that explicit. Use `disableAllHooks` only in a run that has no tools that act.
- A permission rule names an absolute path with two leading slashes (`Read(//Users/me/x/**)`); one slash means relative to the settings file, so a deny written that way silently lets the arm read what it should not.
- Do not change `HOME` or `CLAUDE_CONFIG_DIR` to isolate a run: the login does not follow. Blocking every other project also blocks the transcripts that hold the answer for requests that depend on them.
- `--disallowedTools 'Skill(<name>)'` keeps a skill out of an arm, but a no-skill arm told to follow "the conventions skill" goes looking for it by path, so deny reading its files as well. The `write-policy.ts` hook adds skill-design's edit-time hint to the first `SKILL.md` edit of any session, a no-skill arm's included, so a replay that compares skill-design itself runs with `CLAUDE_SKILL_HINT_SKIP=1`, which suppresses only the hint. Confirm in each transcript that the skill an arm is meant to use was loaded, or the arm quietly becomes the no-skill arm.
- Parallel runs that write to the same path mix their output; give each run its own directory.
- `--no-session-persistence` keeps the replay's transcripts out of `~/.claude/projects`, where they would skew later transcript counts; it still leaves an empty project directory and a `meta.json` per subagent there.
- A run that drives agent-browser leaves its daemon behind; close the replay's own session with `agent-browser --session <name> close`.

## Reading the result

- Judge outputs blind: neutral labels, one judge for all arms, and candidates that never see the words "eval" or "candidate". Read every output yourself as well before trusting the ranking.
- Count tool calls and which files were read from the transcript: a skill that changes research or reading shows it there before it shows in the output.
- `claude -p --resume <id> --fork-session` reports a cost that includes the base session, and its new turns are cut out by message uuid, not by timestamp.
- What the user judges by feel (tone, look, whether a conversation felt formal) does not come out of a replay; report it as unmeasured and leave it to real use.
